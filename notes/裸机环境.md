## 从你熟悉的场景出发

你在电脑上写一个 C 程序：

```c
#include <stdio.h>
int main() {
    printf("hello\n");
    return 0;
}
```

编译运行背后发生了什么：

```
你的程序
  ↓ 调用 printf
glibc（C 标准库）
  ↓ 调用 write()
Linux 内核
  ↓ 操作硬件
CPU 执行
```

每一层都依赖下面那一层。最底层是操作系统内核，它管理一切——内存、文件、进程、硬件。

---

## 裸机：去掉操作系统

裸机就是**没有操作系统**。你的程序直接跑在硬件上：

```
你的程序
  ↓ 直接操作
CPU 执行（可能加一层简单的硬件抽象库）
```

没有 Linux，没有 glibc，没有 `printf`，没有 `malloc`，没有文件系统。你写的代码就是整个机器上唯一在跑的东西。

**常见在哪？**

- 单片机：STM32、ESP32、Arduino
- 实时系统：汽车 ECU、工业控制器、无人机飞控
- 物联网设备：智能灯泡、传感器节点

---

## 没有 OS 意味着什么

### 1. 没有 main

普通程序的 `main` 其实不是真正的入口——glibc 在 `main` 之前做了一堆初始化（设置堆、初始化 stdio 等），然后才调你的 `main`。裸机上没有这些，真正的入口是**复位向量**：CPU 上电后从固定地址开始执行，你的第一行代码就得自己处理一切。

```c
// 裸机入口，通常叫 Reset_Handler 之类的
void Reset_Handler(void) {
    // 第一步：初始化硬件
    system_clock_init();
    // 第二步：把 .data 段从 flash 拷到 RAM
    // 第三步：清零 .bss 段
    // 第四步：现在才能开始干活
}
```

### 2. 没有 malloc

没有操作系统，内存布局全由你自己定。通常你在编译时就规划好了：

```c
// 静态分配，编译时大小就确定了
uint8_t heap[64 * 1024];  // 64KB 的"堆"
uint8_t stack[4 * 1024];  // 4KB 栈
```

如果要动态分配，你得自己实现或移植一个分配器（比如 WAMR 里用的 TLSF）。

### 3. 没有 printf

没有终端，没有 stdout，通常连屏幕都没有。输出靠什么？往串口寄存器写字节，另一端用 USB 转串口线接电脑看日志：

```c
void uart_putc(char c) {
    while (*(volatile uint32_t *)0x40002000 & (1 << 5));  // 等发送寄存器空
    *(volatile uint32_t *)0x40002004 = c;                  // 写数据
}
```

### 4. 没有进程/线程

整个芯片上只有一个程序在跑。要做多任务，要么用**中断**（硬件事件触发），要么自己实现简单调度器，要么跑一个 RTOS（FreeRTOS、Zephyr 等）。

### 5. 没有文件系统

程序存在哪？**Flash**（片上闪存）。数据（`.data`、`.bss`）放在 **SRAM**（片上静态 RAM）。典型布局：

```
┌──────────────────┐ 0x08000000  Flash 起始
│  .text  (代码)    │
│  .rodata (常量)   │
│  .data 初值       │  ← 启动时要复制到 RAM
├──────────────────┤
│  (程序结束)       │
└──────────────────┘

┌──────────────────┐ 0x20000000  SRAM 起始
│  .data (已初始化)  │  ← 从 Flash 复制过来
│  .bss  (未初始化)  │  ← 启动时清零
│  heap (堆)        │  ← 向上增长
│  ...              │
│  stack (栈)       │  ← 向下增长
└──────────────────┘
```

## WAMR 在裸机上的角色

你现在应该能理解为什么 WAMR 设计了这么多东西：

| WAMR 的设计 | 为什么 |
|---|---|
| `mem_alloc_type` 三种模式，含 Pool | 裸机没有 malloc，需要预分配静态内存池 |
| `WASM_ENABLE_LIBC_BUILTIN` | 裸机没有 libc，WAMR 自带了最小实现 |
| 平台抽象层 15+ 个 `platform_internal.h` | 每个平台操作硬件的 API 都不一样 |
| `bh_*` 前缀的基础库 | 不依赖任何 OS API，纯 C 实现 |
| `wasm_memory_init_with_pool(地址, 大小)` | 直接告诉 WAMR 用哪块物理内存 |

## 一个具体的裸机 wasm 场景

```
ESP32 芯片
  └─ FreeRTOS（迷你操作系统，提供线程和内存分配）
       └─ WAMR runtime
            └─ 用户的 .wasm 模块（比如一个传感器数据处理逻辑）

上电后：
1. FreeRTOS 初始化
2. WAMR 用预分配的内存池初始化
3. 加载 .wasm 文件（从 flash 里读）
4. 实例化模块
5. wasm 里跑传感器算法，通过导入函数读写 GPIO
```

---

简单说：裸机就是**你写的代码是唯一在跑的东西**，没有 OS 帮你兜底。每一字节内存、每一次硬件操作都得自己管。WAMR 的设计——小体积、可选择内存策略、自建 libc、平台抽象——就是为这种环境量体裁衣的。
